

# 企业信息页面实现方案

## 概述
根据PRD文档，实现企业信息页面，包含两大区域：基本信息（企业名称、企业ID、创建时间、管理员管理）和企业认证（认证状态展示与申请流程）。

---

## 1. 数据库变更

### 新建 `enterprise_certifications` 表
用于存储企业认证信息和状态。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | uuid | 主键 |
| enterprise_id | uuid | 关联企业（唯一） |
| status | text | 认证状态：uncertified / pending / certified / rejected |
| company_name | text | 企业注册名称 |
| credit_code | text | 统一社会信用代码 |
| legal_person | text | 法人信息 |
| business_license_url | text | 营业执照URL（可选） |
| submitted_at | timestamptz | 提交时间 |
| reviewed_at | timestamptz | 审核时间 |
| created_at | timestamptz | 创建时间 |

### 为 members 表添加 UPDATE 权限
当前 members 表不允许 UPDATE，但管理员管理功能（新增/转移/移除管理员）需要更新角色字段。需添加 UPDATE RLS 策略。

## 2. 页面结构

### 上半部分：基本信息卡片
- **企业名称**：展示当前名称，未认证状态下可编辑（点击编辑图标进入编辑模式）；已认证后不可修改
- **企业ID**：显示 enterprise_code，系统唯一标识，不可修改，旁边带复制按钮
- **企业创建时间**：格式化展示 created_at
- **企业管理员**：列出当前所有 role=admin 的成员手机号，旁边有"管理"按钮

### 管理员管理弹窗（仅管理员可见）
点击"管理"按钮弹出对话框，提供三个操作标签页：
1. **新增管理员**：从现有企业成员中选择，确认后将其 role 更新为 admin
2. **转移管理员**：选择新管理员，确认后新管理员升级为 admin，当前操作人降级为 member（原子操作）
3. **移除管理员**：选择要移除的管理员，系统校验管理员数量必须大于1，确认后降级为 member

### 下半部分：企业认证区域
根据认证状态动态展示：
- **未认证**：显示提示文字"该企业尚未认证"，提供"立即认证"按钮
- **认证中（审核中）**：显示"认证审核中，请等待后台人工审核"状态提示，不可重复提交
- **已认证**：展示认证信息（企业注册名称、统一社会信用代码、法人信息、营业执照）
- **认证失败**：显示失败提示，允许重新提交

### 认证申请表单弹窗
点击"立即认证"后弹出表单：
- 企业注册名称（必填）
- 统一社会信用代码（必填）
- 法人信息（必填）
- 营业执照（可选，当前版本仅文本输入，简化处理）
- 提交后状态变为"pending"（审核中）

## 5. 边界情况处理

- 企业必须至少保留一名管理员，移除时校验数量
- 转移管理员为原子操作：新管理员赋权与当前操作人降级在同一事务中完成
- 已认证企业不允许修改企业名称
- 审核中状态不允许重复提交认证申请
- 仅管理员可见"管理"按钮和认证申请功能
- 企业名称修改后，如已通过认证需重新发起认证（当前版本认证不影响功能使用）
