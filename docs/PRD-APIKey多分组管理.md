# API Key 多分组管理 - 产品需求文档 (PRD)

**版本**: v1.0  
**日期**: 2026-04-27  
**状态**: 已开发完成  

---

## 1. 需求背景

### 1.1 业务背景
原系统仅支持为 API Key 设置单一分组，无法满足企业复杂的成本控制、路由策略和优先级管理需求。企业用户需要为同一个 API Key 配置多个成本渠道，当同一模型在多个分组中存在时，按优先级顺序依次调用，以实现成本优化和故障降级。

### 1.2 目标用户
- **企业管理员**：为部门创建 API Key，配置多分组策略
- **部门管理员**：管理本部门 API Key 的分组配置

### 1.3 核心目标
1. 支持单个 API Key 绑定多个分组
2. 支持通过拖拽调整分组优先级顺序
3. 同一模型在多个分组中存在时，分组顺序决定调用优先级（排在前面的优先级更高）
4. 向后兼容单分组历史数据

---

## 2. 术语定义

| 术语 | 说明 |
|------|------|
| 分组（Group） | 带有折扣系数的渠道类别，如"生产通道（×0.95）" |
| 优先级顺序 | 分组数组的索引顺序，索引越小优先级越高 |
| 折扣系数 | 分组名称中的价格倍率，如 ×0.95 表示95折 |
| 模型路由 | 根据分组优先级决定从哪个分组调用指定模型 |

---

## 3. 分组选项配置

系统预置以下分组选项，每个分组包含折扣系数：

| 分组名称 | 折扣系数 | 适用场景 |
|----------|----------|----------|
| 官方价格 | ×1.0 | 标准定价，无折扣 |
| 生产通道 | ×0.95 | 生产环境，95折优惠 |
| 测试环境 | ×0.8 | 测试环境，8折优惠 |
| 开发环境 | ×0.7 | 开发环境，7折优惠 |
| 内部工具 | ×0.5 | 内部工具，5折优惠 |
| Claude-原厂直连 | ×0.85 | Claude官方渠道 |
| Claude-Code | ×0.9 | Claude代码模型 |
| GPT-4专线 | ×0.88 | GPT-4专属通道 |
| 通用模型池 | ×0.92 | 多模型聚合 |
| 经济型通道 | ×0.75 | 低成本场景 |

## 4. 创建/编辑 API Key

### 4.1 分组选择组件

#### 4.1.1 组件位置
位于表单"基本信息"区域，是必填项（标记红色星号 *）。

#### 4.1.2 布局结构

```

│ ┌─────────────────────────────────────────────────┐ │

│ │ 生产通道（×0.95）  ×                            │ │
│ │                                                 │ │
│ │ 拖拽标签可调整优先级顺序，同一模型在多个分组中   │ │  ← 灰字说明
│ │ 存在时，优先使用排在前面的分组                    │ │
│ └─────────────────────────────────────────────────┘ │
│ ┌─────────────────────────────────────────────────┐ │
│ │ 已选择 3 个分组                          ▲      │ │  ← 下拉触发区
│ └─────────────────────────────────────────────────┘ │
│ ┌─────────────────────────────────────────────────┐ │
│ │ 🔍 搜索分组...                                   │ │  ← 搜索框
│ ├─────────────────────────────────────────────────┤ │
│ │ ☑ 官方价格（×1.0）                      已选    │ │  ← 选项列表
│ │ ☑ 生产通道（×0.95）                     已选    │ │
│ │ ☑ 测试环境（×0.8）                      已选    │ │
│ │ ☐ 开发环境（×0.7）                              │ │
│ │ ☐ 内部工具（×0.5）                              │ │
│ │                                                 │ │
│ │ 已选择 3 个                        [清空]       │ │  ← 底部统计
│ └─────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────┘
```

#### 4.1.3 已选分组展示区域

**位置**：下拉框上方  
**样式**：带边框的圆角容器，内含：
- 已选分组标签（带删除按钮 ×）
- 灰字说明："拖拽标签可调整优先级顺序，同一模型在多个分组中存在时，优先使用排在前面的分组"

**交互规则**：
- 点击 × 移除对应分组
- 拖拽标签可调整顺序
- 标签顺序 = 优先级顺序（从左到右，优先级递减）

#### 4.1.4 下拉面板功能

| 功能 | 说明 |
|------|------|
| 搜索框 | 支持按分组名称关键字过滤 |
| 复选框列表 | 勾选/取消选择分组 |
| 已选标记 | 已选中的分组右侧显示"已选"标签 |
| 底部统计 | 左下角显示"已选择 N 个" |
| 清空按钮 | 右下角一键清空所有选择 |

#### 4.1.5 拖拽排序逻辑

- 长按已选分组标签可拖拽
- 拖拽时标签跟随鼠标移动
- 放置到目标位置后，分组顺序重新排列
- 新顺序实时同步到展示区域

## 5. API Key 列表展示

### 5.1 分组列展示规则

**多分组展示样式**：
```
分组列内容：

Claude-原厂直连（×0.85） → Claude-Code（×0.9） → A-通用渠道-全站模型可用（×0.95）

或

官方价格（×1.0） → 生产通道（×0.95） → 测试环境（×0.8） → 开发环境（×0.7） → 内部工具（×0.5）
```

**展示规则**：
- 多个分组用灰色箭头（→）连接
- 顺序即为优先级顺序（左高右低）
- 分组名称保持完整显示（含折扣括号）
- 内容超长时自动换行显示

### 5.2 数据兼容展示

| 数据类型 | 展示方式 |
|----------|----------|
| 新数据（多分组数组） | 用箭头连接显示所有分组 |
| 旧数据（单分组字符串） | 直接显示分组名称 |
| 无分组数据 | 显示占位符 "—" |

## 6. 业务规则

### 6.1 分组优先级语义

**核心逻辑**：优先级是针对同一模型在多个分组中存在时的调用顺序，而非分组本身的通用优先级。

| 优先级位置 | 业务含义 |
|------------|----------|
| 第1位（最左） | 当同一模型存在于多个分组时，优先从此分组调用 |
| 第2位 | 第1位分组无可用令牌或失败时，降级到此分组调用同一模型 |
| 第3位及以后 | 依次降级备选，形成完整的路由链 |

**示例场景**：
- Key A 配置了分组：`[生产通道（×0.95）, 测试环境（×0.8）]`
- 两个分组都包含 `gpt-4` 模型
- 用户调用 `gpt-4` 时，系统优先从"生产通道"分配令牌
- 当"生产通道"的 gpt-4 无可用额度时，自动降级到"测试环境"继续请求同一模型

### 6.2 "生产通道"特殊逻辑

当选择的分组中包含"生产通道"时：
- 模型限制列表自动禁用
- 显示文案："仅支持分组对应模型列表"
- 系统根据分组配置自动匹配可用模型
- 用户无法手动指定模型白名单

### 6.3 数据存储规则

- **多分组字段**：以数组形式存储完整的分组列表
- **兼容字段**：取数组第一个元素作为单分组字段存储，确保旧系统兼容
- **编辑回填**：优先读取多分组数组，无数据时回退到单分组字段

## 7. 边界情况处理

| 场景 | 处理方式 |
|------|----------|
| 未选择任何分组 | 表单提交时校验失败，提示"请选择分组" |
| 搜索无结果 | 下拉面板显示"未找到分组"提示 |
| 只选择一个分组 | 不显示箭头连接符，仅显示单个分组 |
| 重复选择 | 同一分组不能重复添加 |
| 全部分组已选 | 其他选项置灰不可选 |
| 旧数据编辑 | 单分组回填到多选组件，可继续添加其他分组 |

| 场景 | 预期结果 |
|------|----------|
| 创建Key选择3个分组 | 列表展示3个分组，用箭头连接 |

| 同一模型在多分组中 | 按优先级顺序决定调用来源 |
